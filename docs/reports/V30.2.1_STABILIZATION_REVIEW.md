## Independent candidate review

A separate read-only investigator confirmed the original export/logging paths.
A fresh read-only candidate reviewer then found four additional cases: secret
aliases (`GITHUB_TOKEN`, `refresh_token`, `client_secret`, `AWS_SECRET_ACCESS_KEY`),
old firmware success evidence, untouched old log permissions/content, and
missing/unchanged current firmware versions. The main agent reproduced and
addressed those cases, with focused regressions. Authorization and proxy
authorization JSON headers are also redacted; separate secret argv flags are
handled across new and historical entries. Historical log reads repair only
permissions and redact returned data; content is sanitized on the next locked
write/trim. This is one independent review cycle, not a claim of exhaustive
security certification.

Firmware history must contain a matching successful release modified no earlier
than the execution start, allowing fwupd's whole-second timestamp precision.
Missing/old/undated history cannot prove success: it remains pending before
reboot and fails after reboot. An explicit failed update fails immediately.
Old plans without complete versioned facts require fresh review; stored history
is preserved. Serialization and state values were checked against the upstream
[fwupd device serializer](https://github.com/fwupd/fwupd/blob/main/libfwupd/fwupd-device.c),
[release serializer](https://github.com/fwupd/fwupd/blob/main/libfwupd/fwupd-release.c),
and [update-state definitions](https://github.com/fwupd/fwupd/blob/main/libfwupd/fwupd-enums.rs).

## Recovery and evidence limits

Corrupt plan input and `.lkg` files must be preserved and inspected before
explicit recovery. Health / System Check exposes state-integrity findings and
source failures; the separate CLI `doctor` inspects dependencies/platform/Polkit.
See [state recovery guidance](../STATE_INTEGRITY.md).

Package qualification tests the installed candidate in a disposable Fedora 44
container as a regular user. It does not establish physical KDE/GNOME,
Traditional/Atomic, Polkit prompts, firmware hardware, keyboard, scaling, or
audible Orca behavior. These remain `unverified`. Runtime Fedora 43/44
compatibility is separate from the Fedora 44 package qualification performed.

Retired-module cleanup, AppImage, and a wider distribution matrix remain deferred.
Broad internal command classification remains a risk; no publicly reachable
exploit was established in this review. No new automatic repair, rollback,
retry, reboot, or alternate mutation authority is introduced.
